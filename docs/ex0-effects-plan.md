# 0th拡張の効果を自動処理にするための作業表

0th拡張（0th EDITION 拡張）の33種を、**1枚ずつ自動処理にしていく**ための調べ書き。
カードの絵・データ・文・テストモードまでは入っている（続き649）。ここは**効果だけ**の話。

## 大前提

🔴 **効果データが在るカードだけが自動処理される。** `CARD_EFFECTS` に載っていないカードは
今までどおり**文を読んでプレイヤーが自分で処理する**（ユドンリウムコネクト方式＝このプロジェクトの
元々の段階目標）。だから**半端なデータを置くのは、何も置かないより悪い**——間違った処理が勝手に走る。
**1枚を最後まで仕上げてから載せる。**

ⓘ `canAutoProcessArrival` は `.arrival` か `.arrivalOptions` が在るかだけを見る。
つまり**「手札効果だけ自動・到達は手動」も作りとしては成立する**（ファーストカードがその形）。
ただし通常カードでそれをやると**半分だけ自動**という分かりにくい状態になるので、
基本は**到達・手札の両方がそろってから載せる**。

## 1枚を仕上げるのに触る4か所

| | |
|---|---|
| `src/card-effects.js` の `VERBS` | 新しい動詞を足す |
| `src/card-effects.js` の `CARD_EFFECTS` | そのカードの効果データ |
| `src/card-effects.js` の `renderAction` | 効果文の組み立て（カード開発モードの照合に使う） |
| `src/card-effect-engine.js` | 動詞を実際に動かす所 |
| `test/effect-cases.mjs` | テスト（持ち物検査が「1件でもあるか」を見る） |

**済んだ例**: `ex0-red-beginning`（赤のはじまり）。`PICKUP_DISCARD_TOP` を1つ足しただけで、
到達・手札の両方が完成した。テスト2件つき。**これが型。**

## いま使える動詞のうち、0th拡張で効くもの

`DRAW` / `MOVE` / `PICKUP_TO_HAND` / `PLACE_CARD` / `DISCARD_SAME_COLOR`（追色）/
`END_CURRENT_PHASE` / `INHERIT_ARRIVAL_ACTIONS` / `DISCARD_ALL_AT_CHOSEN_CELL` /
`FORCED_MOVE_TO_OWN_GATE` / `LOCK_ONE_HAND_CARD_EXCEPT_FINAL` /
`PLACE_SELF_ADJACENT_TO_CHOSEN_OPPONENT` / `ALL_PLAYERS_DISCARD_TO_THREE` /
`PICKUP_DISCARD_SECOND_FROM_TOP` / `DISCARD_HALF_HAND` / `DECLARE_COLORS`

🔴 **無いもので、何枚にも効くもの**:
- **ふつうの「強制移動」**（いまは「自分のゲートへ」しか無い）。22・32・03・10 が要る。
- **「このターンを終了する」**（`END_CURRENT_PHASE` はフェイズだけ）。13・22・23・24・26 が要る。
- **マスの「１番下」に置く**（いまは一番上だけ）。07 が要る。
- **裏向きのカードの表面を「見る」**（オープンせずに本人だけ見る）。05・26 が要る。
- **「このターンにこのカードがオープンされたか」の記録**。09・10 が要る。

## 決まっていること（実装時に忘れない）

- **ファーストカード・エターナルカードはリメイクのものを使う**（ユーザー確認済み）。0th拡張には無い。
- **なないろの欠片はリメイクのものと同じ**（文も絵も）。0th拡張としては作っていない。
- **紅の鉄拳の S** は使う人が決める。**手札にある赤のカードの枚数まで**。
  **Sは1以上**なので、赤が手札に1枚も無いならこの手札効果は**使えない**（＝そもそも光らせない）。
- **ONLYカードは1枚ずつ**しか山札に入らない（データに入れてある）。
